# QQ 主动提醒

用机器人的身份给用户发 QQ 消息。脚本自己读机器人目录下 `.env` 里的凭据和白名单，机器人进程不用开着。

```powershell
node "{{NOTIFY_SCRIPT}}" '要发的内容'
```

- 默认发给白名单里唯一的那个用户。发到群用 `--group <群 openid>`，发给指定用户用 `--to <openid>`，都必须在白名单里。
- 附图：`--image <路径>`，可以写多次，最多 3 张，png/jpg/gif/webp，单张不超过 5MB。图片在文字之后发出。
- 内容多行或带引号时，先写进一个 UTF-8 文件，再用 `--file <路径>` 发送。
- 加 `--dry-run` 只显示会发给谁、发什么，不真的发送。
- PowerShell 里内容用单引号包起来：双引号里的 `$` 会被当成变量。
- 内容按 Markdown 写，可以用简单的列表和代码块，不要用表格、HTML 和多级标题。超过 1800 字会自动分成多条，超过 5 条会截断，完整内容存到本机，并在消息里附上路径。

成功时输出「已发送到 …」，退出码 0。退出码 1 是发送失败（网络问题或 QQ 平台拒绝，可能已经发出一部分，看输出）；2 是参数或配置有误，什么都没发。

## 规则

- 每次运行最多发一次：要说的合成一条发，不要为同一件事重复发。
- 没有值得通知的事（监控的状态没变、检查一切正常）就不发，除非任务要求每次都汇报。
- 用户在 QQ 上看到时没有上下文：第一句写清是哪个任务或提醒，再写结论和需要用户做的事。控制在几百字以内，长的细节存成本机文件，消息里给出路径。
- 发送失败最多重试一次，然后把脚本输出的错误原样写进本次任务的结果。错误和主动消息有关时，提醒用户检查机器人资料卡里的「允许主动发送」。
- 如果你的指令里写着「你正在通过 QQ 机器人与用户对话」，你的回复本来就会发到 QQ，直接回复即可，不要再用这个脚本，否则用户会收到两遍。
- 不要读取或输出机器人目录下的 `.env`，不要发送密钥、密码、Cookie 等敏感信息。

## 用在计划任务里

在 Codex 桌面版建计划任务时，提示词里点名用 qq-notify，并写清什么情况发、什么情况不发，例如：

> 每周五 17:00 用 qq-notify 提醒我交周报。

> 每个交易日 14:50 查一下 600519 的价格，跌破 1500 元时用 qq-notify 把价格和当天涨跌幅发到 QQ；没跌破就不要发。
